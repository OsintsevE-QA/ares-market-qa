# Тестовый сценарий: TS-AUTH-002 - Вход, проверка профиля и безопасный выход

## Описание

Существующий пользователь входит в систему, проверяет свой профиль, выполняет logout и подтверждает, что сессия завершена корректно.

## Предусловия

- AresMarket запущен локально
- В системе существует пользователь с известными учетными данными (например, `nova` / `nova123`)
- Пользователь не авторизован

## Шаги сценария

1. Открыть страницу входа
2. Ввести валидные учетные данные
3. Подтвердить успешный вход (UI показывает username и badge роли)
4. Проверить, что клиент сохранил JWT-токен (способ хранения — localStorage / sessionStorage / cookie - уточняется по реализации, см. «Требуется уточнение», п. 10 в TD-AUTH.md)
5. Открыть профиль через `/api/auth/me` с токеном
6. Подтвердить, что профиль содержит корректные данные пользователя и роль
7. Нажать кнопку "Выход" в UI
8. Подтвердить, что UI вернулся в состояние неавторизованного пользователя (badge роли исчез, меню показывает "Вход"/"Регистрация")
9. Подтвердить, что клиент отбросил токен (localStorage очищен)
10. Попытаться обратиться к защищенному эндпоинту (например, `/api/auth/me`) со старым токеном
11. Подтвердить поведение сервера (см. "Требуется уточнение" - сервер может принять или отклонить старый токен)

## Ожидаемый результат

- Вход работает корректно
- Профиль отображает правильные данные
- Logout завершает сессию на клиенте
- UI корректно отображает состояние неавторизованного пользователя
- Поведение сервера со старым токеном соответствует документации (или требует уточнения)
